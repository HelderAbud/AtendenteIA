# AtendeIA Postgres Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Guardar a lista de encaminhamentos no Postgres para ela sobreviver ao reinício sem o arquivo SQLite.

**Architecture:** `Fila` em SQLite fica para os testes sem URL. `FilaPostgres` abre uma conexão nova a cada chamada. O atendimento e a API só repassam a URL. O `app` do módulo lê `ATENDEIA_DATABASE_URL`. Sem a variável, a lista volta a ser só daquele processo. Login e WhatsApp ficam fora.

**Tech Stack:** Python 3.14, FastAPI, pytest, psycopg 3 com extra `binary`, Postgres 18 no Docker do Ubuntu, porta do host 5437.

## Global Constraints

- O tema de chamado continua `chamado`. Não usar `status_chamado`.
- O classificador, `data/vertice_ti.json`, o fluxo e os cinco campos de `POST /v1/perguntas` não mudam. O POST não devolve `id`.
- `GET /health` continua `200` `{ "status": "ok" }` e não consulta o Postgres nem a base de conhecimento.
- Pergunta inválida continua `422` `{ "erro": "pergunta_invalida" }`.
- `DELETE` de id ausente continua `404` `{ "erro": "encaminhamento_inexistente" }` e não lê a base de conhecimento.
- A tabela é `encaminhamentos` com `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, `pergunta TEXT NOT NULL`, `fluxo TEXT NOT NULL`, `resumo TEXT`.
- `id` começa em 1 e não é reutilizado, nem depois de apagar e nem depois de uma conexão nova.
- `resumo` nulo vai como `NULL` e volta como `None`. A lista sai em ordem de `id`.
- Sem URL, o comportamento atual da `Fila` permanece. Com a mesma URL, dois objetos veem as mesmas linhas.
- O `app` do módulo não abre mais `data/atendeia.sqlite`.
- A porta do host é 5437. Não usar o PostgreSQL 18 do Windows na 5432.
- Docker só no Ubuntu. Não há Docker no PowerShell deste PC.
- Sem login, WhatsApp, modelo de linguagem, Alembic ou pool de conexão.
- Não alterar o exemplo JSON de três campos no README.
- Commit só quando o usuário pedir nesta sessão.
- A senha `atendeia` é só do Postgres local de desenvolvimento. Não criar outra senha e não commitar `.env`.

`app/fila_postgres.py`:

```python
import psycopg


class FilaPostgres:
    def __init__(self, url: str) -> None:
        self._url = url
        with self._conectar() as conexao:
            conexao.execute(
                """
                CREATE TABLE IF NOT EXISTS encaminhamentos (
                    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
                    pergunta TEXT NOT NULL,
                    fluxo TEXT NOT NULL,
                    resumo TEXT
                )
                """
            )
            conexao.commit()

    def _conectar(self) -> psycopg.Connection:
        return psycopg.connect(self._url)

    def registrar(self, pergunta: str, fluxo: str, resumo: str | None) -> None:
        with self._conectar() as conexao:
            conexao.execute(
                "INSERT INTO encaminhamentos (pergunta, fluxo, resumo) VALUES (%s, %s, %s)",
                (pergunta, fluxo, resumo),
            )
            conexao.commit()

    def listar(self) -> list[dict]:
        with self._conectar() as conexao:
            linhas = conexao.execute(
                "SELECT id, pergunta, fluxo, resumo FROM encaminhamentos ORDER BY id"
            ).fetchall()
        return [
            {"id": linha[0], "pergunta": linha[1], "fluxo": linha[2], "resumo": linha[3]}
            for linha in linhas
        ]

    def remover(self, item_id: int) -> None:
        with self._conectar() as conexao:
            cursor = conexao.execute(
                "DELETE FROM encaminhamentos WHERE id = %s", (item_id,)
            )
            conexao.commit()
            if cursor.rowcount == 0:
                raise KeyError(item_id)
```
